<api_contract>
These shapes are shared by every task in this plan and by plan 02-02. All JSON keys are camelCase.

- **Ids.** All ids are JSON strings: BIGINT ids as decimal strings, cart/order/customer ids as UUID strings. Inputs accept a decimal string, or (in JSON bodies) a positive safe integer, and normalize it to a string.
- **Money.** Arithmetic stays in PostgreSQL NUMERIC (line totals and subtotals are computed in SQL). Values become JSON numbers only at serialization, for example `54990` or `54990.5`.
- **Error envelope.** Every non-2xx response is `{ "error": { "code": "UPPER_SNAKE", "message": "human readable", "details": optional object, "requestId": request.id } }`. The codes are:
  - 400 `VALIDATION_FAILED`, with `details.issues` as `[{ path: "query.limit", message }]`.
  - 400/413/415 Fastify built-in client errors, passed through with their own `code` (e.g. `FST_ERR_CTP_INVALID_JSON`) and message.
  - 404 `ROUTE_NOT_FOUND`, `PRODUCT_NOT_FOUND`, `LOCATION_NOT_FOUND`, `CART_NOT_FOUND`, `CART_ITEM_NOT_FOUND`.
  - 409 `CART_NOT_ACTIVE` (`details.status`) and `PRODUCT_UNAVAILABLE` (inactive product).
  - 422 `QUANTITY_LIMIT_EXCEEDED`.
  - 500 `INTERNAL_ERROR`, whose message is always the fixed text "Internal server error".
- **Collections.** Collections are `{ "items": [...] }`. Single resources are wrapped by name: `{ "product": {...} }`, `{ "cart": {...} }`.
- **Product.** `{ id, sku, name, description, price, imageUrl, category: { id, slug, name }, inventory: [{ locationId, locationName, city, stockQuantity }], totalStock, inStock }`. `inventory` lists every store that carries the product (an inventory row exists), ordered by location id.
- **Cart.** `{ id, status, locationId, location: { id, name, city } | null, orderId: string | null, items: [{ productId, sku, name, imageUrl, unitPrice, quantity, lineTotal, availableQuantity }], itemCount, subtotal, createdAt, updatedAt }`.
  - `availableQuantity` is the current stock at the cart's store, or 0 if that store does not carry the product. It is informational only: carts never reserve stock, and checkout (02-02) is the only stock authority.
  - `itemCount` is the sum of quantities.
  - `orderId` is set once the cart is checked out (from `orders.cart_id`).
</api_contract>

1. Create `backend/src/store/carts.ts`. Each mutation runs inside `db.transaction`.
   - `lockActiveCart(tx, cartId)` issues `SELECT id, status, location_id FROM carts WHERE id = $1 FOR UPDATE`.
     - No row means 404 `CART_NOT_FOUND`. A status other than `active` means 409 `CART_NOT_ACTIVE` with `details.status`.
     - Every mutation calls it first. This row lock is the contract plan 02-02's checkout relies on: checkout locks the same cart row, so a concurrent add-item either finishes before checkout reads the items or waits and is then rejected because the cart is checked out. No item can slip in after checkout has locked the stock.
   - `createCart(db, { locationId })`: `INSERT INTO carts (location_id) SELECT id FROM store_locations WHERE id = $1 RETURNING id`. No row means 404 `LOCATION_NOT_FOUND`.
   - `addCartItem(db, cartId, { productId, quantity })`:
     - Lock the cart.
     - Check the product: `SELECT id, is_active FROM products WHERE id = $1`. Missing means 404 `PRODUCT_NOT_FOUND`; inactive means 409 `PRODUCT_UNAVAILABLE`.
     - Upsert with `INSERT ... ON CONFLICT ON CONSTRAINT cart_items_cart_product_key DO UPDATE SET quantity = cart_items.quantity + EXCLUDED.quantity WHERE cart_items.quantity + EXCLUDED.quantity <= 99 RETURNING quantity`. No returned row means 422 `QUANTITY_LIMIT_EXCEEDED`.

   - `setCartItemQuantity`: lock, then `UPDATE cart_items ... RETURNING`. No row means 404 `CART_ITEM_NOT_FOUND`.
   - `removeCartItem`: lock, then `DELETE ... RETURNING`. No row means 404 `CART_ITEM_NOT_FOUND`.
   - `setCartLocation`: lock, then `UPDATE carts SET location_id = l.id FROM store_locations l WHERE carts.id = $1 AND l.id = $2 RETURNING carts.id`. No row means 404 `LOCATION_NOT_FOUND`.

     - No cart means 404 `CART_NOT_FOUND`.

   - Carts never check or reserve stock (`availableQuantity` is informational).
